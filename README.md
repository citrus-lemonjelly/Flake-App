# Flake

Debt payoff and paycheck budgeting for a household. Plan each paycheck, log spending in a few taps, check in with your bank balance on payday, and see when every debt will be gone.

**Live app:** https://citrus-lemonjelly.github.io/Flake-App/

A local-first web app (Vite + React + TypeScript). It installs to a phone's home screen, works offline, and syncs between devices through Supabase. An iOS App Store build through Capacitor comes later.

## Install it on a phone

- **iPhone:** open the link in Safari → Share → **Add to Home Screen**.
- **Android:** open the link in Chrome → menu → **Install app**.

The installed app keeps its own copy of your data. Sign in under Settings → Sync to keep it in step with your other devices.

## How it's built

| Area | What it does |
|---|---|
| `src/engine/` | Pure calculations: pay calendar (weekend/holiday paydays), per-paycheck plans, debt payoff simulation and strategy comparison, mortgage amortization, milestones, check-ins and the conservative "safe to spend" estimate. |
| `src/model/` | The data model, defaults, and zod validation for backups and storage. |
| `src/store/` | Pure actions, an observable store, IndexedDB storage, JSON backup export/import. |
| `src/sync/` | Record-level sync with Supabase: each record merges on its own and the newer edit wins; deletions travel as tombstones. |
| `src/screens/`, `src/sheets/`, `src/ui/` | The interface (Look B, six color schemes, light/dark). |
| `public/` | Manifest, icons (generated by `scripts/make-icons.mjs`), and the offline service worker. |

Money is integer cents everywhere. Dates are `YYYY-MM-DD` strings with UTC math.

## Deploying

Every push to `main` runs `.github/workflows/deploy.yml`: tests, build, then publish to GitHub Pages. Work on a branch and merge to `main` to ship.

## Sync setup (one time)

1. In the Supabase dashboard, open **SQL Editor**, paste `supabase/schema.sql`, and run it. It creates one table with row-level security (each login sees only its own rows) and a push function that never lets an older edit overwrite a newer one.
2. **Authentication → URL Configuration:** set the Site URL to `https://citrus-lemonjelly.github.io/Flake-App/`, and add `http://localhost:5173` to the redirect URLs for local development.
3. Add the project URL and its publishable (anon) key as repository variables `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` (Settings → Secrets and variables → Actions → Variables). For local development, put the same two lines in `.env.local`. The key is meant to be public; the row-level security policies are what protect the data.

Without those variables the app builds with sync turned off and keeps everything on the device.

## Private data

The repo is public, so household numbers never go in it. `local/` is gitignored and holds the real household seed, tests that check the engine against the original spreadsheet, and design previews built from the real numbers. `src/data/sample.ts` is a made-up demo household.
